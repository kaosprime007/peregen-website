# Security Policy

## Reporting a vulnerability

Please report suspected security vulnerabilities privately. Do not open a public GitHub issue or post exploit details publicly.

Use GitHub's **Report a vulnerability** option in the repository's **Security** tab (private vulnerability reporting or a security advisory). If that option is unavailable, contact the repository owner privately through GitHub and include a link to this repository.

Please include:

- A clear description of the issue and its impact
- The affected URL, file, or commit
- Reproduction steps or a minimal proof of concept
- Any relevant logs, screenshots, or suggested mitigation

Please do not include passwords, API keys, tokens, personal data, or other secrets in a report.

## Scope

This policy covers the Peregen source code, its GitHub Pages deployment, and the `peregenai.com` website configuration maintained in this repository.

Reports about GitHub, Cloudflare, third-party libraries, or third-party services should be sent to the relevant provider as well. Dependency vulnerabilities are still useful to report here when they affect Peregen's build or deployment.

## Disclosure

Please allow reasonable time for investigation and remediation before public disclosure. We will acknowledge valid reports, keep the reporter informed when practical, and coordinate disclosure timing where appropriate.

## Safe testing

Only test systems and data you own or have explicit permission to test. Do not perform denial-of-service testing, social engineering, credential attacks, privacy-invasive testing, or actions that modify or destroy data.
